# Submit Workflow

The `/submit` form loads active category options from D1 and opens a prefilled GitHub
issue. It never writes the production database from the browser.

A maintainer reviews an accepted submission, records a proposal under
`d1/proposals/`, and authors a versioned publication manifest under
`d1/publications/`. The protected publication workflow creates a backup, validates
the current version and checksum, and applies the manifest as one D1 batch.

The application form lives in
`packages/web-core/src/forms/github-issue-submit-form.tsx`. The GitHub target lives in
`sites/serp.software/site-config.ts`.
